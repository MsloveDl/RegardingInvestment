# 基于历史相似性匹配的尾盘选股因子策略（完整说明）

## 一、策略概述
本策略旨在每日尾盘（14:55）利用历史数据（日线+分钟线）计算每只个股的两个概率：
- **P_high**：次日盘中最高价 > 当前买入价的概率
- **P_close**：次日收盘价 > 当前买入价的概率

当概率高于设定阈值时，将该个股纳入备选库，作为后续策略的输入因子。

## 二、数据情况
- **日线数据**：覆盖 2024-08-26 至今（约1.5年），字段：date, open, high, low, close, volume（前复权）
- **分钟线数据**：覆盖 2025-08-21 至今（约6个月），1分钟频率，字段：datetime, open, high, low, close, volume
- **股票池**：全A股，需剔除ST、*ST、停牌、上市不满60日的个股
- **指数数据**（可选）：如需大盘特征，获取沪深300等指数的日线数据

## 三、策略核心方法
采用**历史相似性匹配**与**特征工程**相结合的方法：
1. 提取当前交易日（T）的多维特征（日线衍生 + 分钟线衍生）。
2. 在历史数据中找出与当前特征最相似的 K 个交易日（基于标准化后的欧氏距离）。
3. 统计这 K 个交易日的次日表现，得到两个概率。

## 四、特征定义
特征分为两类，所有特征均使用截至 T 日的数据计算，无未来函数。

### 4.1 日线基础特征（全历史区间可用）
| 特征名称 | 计算公式 | 说明 |
|----------|----------|------|
| `pct` | (close_T - close_{T-1}) / close_{T-1} | 当日涨跌幅 |
| `volume_ratio` | volume_T / MA(volume,20)_T | 成交量与20日均量比值 |
| `amplitude` | (high_T - low_T) / close_T | 当日振幅 |
| `rsi` | 基于过去14日收盘价计算的RSI | 经典RSI |
| `close_to_ma20` | (close_T - MA(close,20)_T) / MA(close,20)_T | 收盘价相对20日均线偏离度 |
| `close_to_bb` | (close_T - BB_lower_T) / (BB_upper_T - BB_lower_T) | 布林带位置（参数20,2） |
| `market_pct` | 大盘指数当日涨跌幅 | 可选 |

### 4.2 分钟线增强特征（仅2025-08-21之后可用）
| 特征类别 | 特征名称 | 计算公式 | 说明 |
|----------|----------|------------------------|------|
| 尾盘动量 | `last_30min_pct` | (close_14:55 - close_14:25) / close_14:25 | 最后30分钟涨跌幅 |
| 尾盘成交量 | `last_30min_vol_ratio` | volume_14:25-14:55 / volume_全天 | 最后30分钟成交量占比 |
| 开盘动量 | `open_30min_pct` | (close_10:00 - open) / open | 开盘后30分钟涨跌幅 |
| 日内波动 | `intraday_volatility` | 基于分钟收益率的标准差（全天） | 已实现波动率 |
| 日内振幅 | `intraday_range` | (high_T - low_T) / close_T（分钟线精确） | 日内振幅 |
| 成交分布 | `vwap_dev` | (close_T - VWAP_T) / VWAP_T | 收盘价相对全天VWAP偏离度 |
| 尾盘RSI | `rsi_min15` | 基于15分钟收盘价的RSI（最后15分钟） | 尾盘短期超买超卖 |
| 最大回撤 | `max_drawdown` | (high_T - low_T) / high_T（分钟线精细） | 日内最大回撤幅度 |

注：分钟线特征计算需严格使用截止至14:55的数据。

## 五、相似日匹配算法

### 5.1 历史特征矩阵准备
- 对每只股票，预先计算所有历史交易日的特征向量（分两个阶段：2025-08-21前仅日线特征，之后包含分钟线特征）。
- 存储格式：每只股票一个 parquet 文件，包含 `date` 和所有特征列。
- 同时计算每只股票每个特征的均值（mean）和标准差（std），存储为 JSON 文件（用于标准化）。

### 5.2 当前特征计算
- 实时运行时，根据当前日期（肯定≥2025-08-21），使用当日分钟线和日线数据计算全部特征。
- 对于分钟线特征，从当日分钟线数据中提取指定时间段计算。

### 5.3 标准化
- 对当前特征向量，使用该股票预存的 mean/std 进行 Z-score 标准化。
- 历史特征矩阵在预计算时已完成标准化（或实时标准化，但建议预计算以加速）。

### 5.4 距离计算与相似日筛选
- 计算当前标准化向量与历史标准化特征矩阵（仅选择与当前特征类型匹配的历史日）的欧氏距离。
- 选取距离最小的 K 个历史交易日作为相似日。
- 若历史样本不足（如少于30日），则跳过该股票或返回默认概率0.5。

### 5.5 概率统计
- 对每个相似日，获取其下一个交易日的最高价和收盘价（从日线数据中提取）。
- `P_high` = 相似日中次日最高价 > 当前买入价（14:55价）的个数 / K
- `P_close` = 相似日中次日收盘价 > 当前买入价的个数 / K

## 六、买入价确定
- 买入价 = T 日 14:55 的分钟线 close 价。
- 若该时刻无交易（停牌），则跳过该股票。

## 七、选股逻辑
- 设定阈值 `thresh_high` 和 `thresh_close`（建议0.55~0.6，可调）。
- 若 `P_high >= thresh_high` 或 `P_close >= thresh_close`，则将该股票纳入当日备选库。
- 输出备选库列表（股票代码、买入价、P_high、P_close）至 CSV 文件或数据库。

## 八、回测验证要求
回测需验证策略因子的预测能力，分为两个场景以评估分钟线特征的增量价值。

### 8.1 回测数据
- 日线区间：2024-08-26 至 最新
- 分钟线区间：2025-08-21 至 最新
- 股票池：全A股（剔除ST、停牌、次新）

### 8.2 回测场景
#### 场景A：纯日线特征回测
- 时间区间：2024-09-01 至 2025-08-20（约11个月）
- 仅使用日线基础特征，买入价取当日收盘价（因无分钟线）。
- 相似日匹配历史数据从2024-08-26开始。

#### 场景B：日线+分钟线特征回测
- 时间区间：2025-09-01 至 最新（约6个月）
- 使用全部特征，买入价取14:55分钟线价。
- 相似日匹配历史数据从2025-08-21开始。

### 8.3 回测步骤
1. **预计算**：对所有股票、所有历史日计算特征向量（分场景），存储为 parquet。
2. **每日循环**（从 start_date+60 开始）：
   - 获取当日所有股票的买入价（场景A为收盘价，场景B为14:55价）。
   - 对每只股票：
     a. 加载该股票历史特征矩阵（预计算）和标准化参数。
     b. 计算当日特征向量（注意场景B需分钟线特征）。
     c. 标准化当日特征，与历史特征计算欧氏距离，获取K个相似日。
     d. 统计概率，若概率>=阈值，记录入选。
   - 保存当日入选列表。
3. **次日验证**：
   - 对每只入选股票，获取次日最高价和收盘价。
   - 判断是否满足：次日最高价>买入价，次日收盘价>买入价。
   - 统计命中率等指标。
4. **回测结束**，输出汇总统计。

### 8.4 评价指标
- 命中率（P_high实际命中率、P_close实际命中率）
- 胜率（次日收盘上涨比例）
- 平均收益率（次日收盘相对于买入价的平均涨幅）
- 最大回撤（若构建等权组合）
- 每日入选数量统计
- 可选：IC/IR

### 8.5 参数优化
- K：10~20（因历史样本有限）
- 阈值：0.5, 0.55, 0.6, 0.65
- 特征组合：可测试是否包含分钟线特征的效果差异

## 九、性能优化要求
由于股票池大（约5000只），数据量较大，代码必须考虑性能。

### 9.1 通用优化
- 使用向量化操作（pandas/numpy）代替显式循环。
- 距离计算使用 `scipy.spatial.distance.cdist` 或 numpy 广播，配合 `np.argpartition` 获取最小K个距离。
- 预计算历史特征矩阵并标准化，避免实时重复计算。
- 使用 parquet 格式存储中间数据，读写快。
- 及时释放大对象内存（`del`, `gc.collect()`）。

### 9.2 实时策略优化（MiniQMT）
- **历史特征加载**：由于数据量小（每只股票约120天×15维≈7KB，5000只共约35MB），可一次性将所有股票的历史特征矩阵加载到内存（字典结构）。
- **当前特征计算**：按股票读取当日分钟线，用向量化计算特征。
- **相似日匹配**：使用 `np.linalg.norm(hist - curr, axis=1)` + `argpartition`。
- **并行处理**：若计算速度慢，可使用多线程（concurrent.futures.ThreadPool）处理股票，因计算密集型可能需多进程，但 MiniQMT 环境需测试。
- **数据获取**：提前订阅全市场分钟线行情，或从本地同步文件读取（按日期存储的分钟线文件）。
- **定时启动**：每日14:40启动，预留足够时间。

### 9.3 回测优化
- **预计算特征矩阵**：一次性计算所有股票所有历史日的特征，存储为每只股票一个 parquet。
- **日线次日数据预加载**：构建股票×日期的次日价格矩阵，便于快速查询。
- **回测循环**：按天进行，每天处理全市场股票，但可使用多进程池分配股票任务。
- **内存管理**：分批处理股票（如每次500只），避免内存溢出。
- **缓存**：大盘指数等全局数据加载一次。

### 9.4 代码结构建议
- 数据加载模块：`load_daily(stock, start, end)`、`load_minute(stock, date)`、`load_features(stock)`
- 特征计算模块：`calc_features(stock, date, use_minute=True)`，返回特征向量（Series）
- 相似日匹配模块：`find_similar(stock, curr_feat, k=20)`，返回概率值
- 回测引擎：`run_backtest(config)`，支持参数配置
- 实时策略：`run_realtime()`，集成到 MiniQMT 定时任务

## 十、注意事项
- **未来函数防范**：实时策略中，分钟线特征只能用14:55之前的数据；回测中，次日数据仅用于验证。
- **停牌处理**：若股票停牌，无法买入，需跳过。
- **涨跌停限制**：若当日涨停无法买入，应剔除。
- **数据对齐**：分钟线和日线需使用相同的前复权方式。
- **参数可配置**：K、阈值、特征列表、买入时间等应放在配置文件中。
