## 一、总体评价

策略理念先进，融合了竞价共振、盘中确认与动态风控，具备较高的实战价值。但当前代码实现与规格存在显著偏差，尤其在 **数据准确性、因子完整性、执行时序** 三个方面存在严重问题，若直接实盘将导致策略失效甚至重大亏损。

## 二、核心逻辑漏洞审计

### 1. 板块强度因子 (SS) 计算不准确

**规格要求**：
- SR（涨停共振）：板块内竞价涨幅 > 9.5% 的个股数
- OR（封单强度比）：(板块内涨停股总封单金额) / (板块流通总市值)
- CR（抗撤单因子）：1 - (9:19至9:25总撤单金额 / 9:19总封单金额)

**代码现状**：
- ✅ SR 计算正确（使用 `open/lastClose` 判断涨幅）
- ❌ **OR 计算错误**：使用竞价 `amount`（成交额）代替封单金额。成交额反映已匹配的成交量，无法代表未成交的买盘强度。
- ❌ **CR 完全缺失**：硬编码为 0.8，失去过滤“诱多”功能。
- ⚠️ **数据时机风险**：在 09:25:00 调用 `get_market_data_ex(period='1d', count=1)` 可能获取的是前一日日线数据，而非当日竞价开盘价。

**影响**：SS 因子失真，可能导致选入虚假热点或错过真正强势板块。

### 2. 抛压探测 (SPP) 实现不完整

**规格要求**：同时检查以下四个条件，任一为 True 则标记为高抛压：
1. 开盘跌幅 > 3%
2. 买卖盘挂单失衡比 < 1.5
3. 开盘后第一分钟大单净流出金额 > 过去5日同时段平均值的2倍
4. 现价距离上方最近一个筹码密集套牢区 < 3%

**代码现状**：
- ✅ 条件2 部分实现（检查买卖五档比例）
- ❌ 条件1、3、4 **完全缺失**
- ⚠️ 买卖五档数据在快速行情中可能延迟，且未考虑 Level2 数据刷新频率（大QMT的 `get_full_tick` 更新频率需确认）

**影响**：SPP 过滤能力大幅削弱，可能买入开盘即跌或抛压沉重的个股。

### 3. 个股动量确认点 (MCP) 缺少量能确认

**规格要求**：触发需同时满足：
1. 价格突破 9:30‑9:35 最高价
2. 触发时成交量 > 前5分钟平均每分钟成交量的 150%
3. 该个股 SPP = False

**代码现状**：
- ✅ 条件1 实现
- ❌ **条件2 完全缺失**：仅简单记录当前成交量，未计算前5分钟均值，无比较逻辑
- ⚠️ 条件3 依赖不完整的 SPP

**影响**：可能导致无量突破的假信号，成交无法持续，买入即回落。

### 4. 题材协同性 (TS) 监控窗口不完整

**规格要求**：
- 买入时刻 TS(t) ≥ 70%
- 监控窗口（9:30 至买入时刻）TS(t) 从未跌破 60%

**代码现状**：
- ✅ 检查当前时刻 TS
- ❌ **未监控历史窗口**，无法识别板块热度是否已衰退

**影响**：可能买入板块内独立下跌的个股，缺乏板块保护。

### 5. 时间轴与执行时序问题

**规格要求**：严格按时间轴执行，特别是 9:25 的快照、9:30‑9:45 的动态监控。

**代码现状**：
- ⚠️ `prepare_daily_context` 通过 `run_time` 注册，但日期写死为 `"2026-02-07 09:25:00"`，应使用相对时间。
- ⚠️ T+1 卖出逻辑依赖 `C.is_last_bar()`，在 handlebar 模式下可能不准确；应使用独立定时任务在 9:25:00 触发。
- ⚠️ 9:30‑9:35 为观察期，代码中记录 `high_35` 和 `avg_vol_35`，但 `avg_vol_35` 仅记录最后一 tick 的成交量，未计算均值。

### 6. 状态管理与持久化不足

**规格要求**：状态（板块、个股池、熔断标志）需持久化以应对程序重启。

**代码现状**：
- ✅ 使用 ContextInfo 属性存储，在单个交易日 handlebar 调用间可保留。
- ❌ **未实现跨交易日持久化**，若程序在盘中重启，所有状态丢失，可能导致重复买入或风控失效。

### 7. 全局熔断与风控实现缺陷

**规格要求**：
- 跌停家数 ≤ 5
- 账户当日总浮动亏损 > 3% 时停止开仓
- 龙头炸板保护（10:00 前炸板且 5 分钟未回封，停止该板块监控）

**代码现状**：
- ⚠️ 跌停计算使用固定 -9.8% 阈值，未考虑 ST 股、科创板等差异。
- ✅ 账户熔断检查实现。
- ❌ **龙头炸板保护完全缺失**。

**影响**：无法及时逃离退潮板块，可能买入即将补跌的个股。

## 三、性能瓶颈与工程风险

### 1. 数据获取频繁，延迟累积
- 在 `handlebar` 循环中对每只候选股调用 `C.get_full_tick`，若候选池较大（几十只），每个 tick 都会产生大量 API 调用。
- TS 协同性计算中，每次循环都调用 `C.get_full_tick(members)` 获取整个板块所有成分股的 tick，数据量极大，且可能因网络延迟导致信号滞后。

### 2. 变量作用域错误
- 在 `prepare_daily_context` 中，`sec_data` 定义在板块循环内部，但在个股池初始化部分被引用（`if m in sec_data`），此时 `sec_data` 可能未定义或指向最后一个板块的数据，导致数据错乱。

### 3. 容错与异常处理缺失
- 未对 API 调用失败、数据缺失等情况进行处理，一旦某个股票 tick 获取失败，可能导致后续逻辑中断。

## 四、优化建议

### 1. 数据准确性优化
- **SS 因子**：
  - 封单金额：使用 9:25 的 `get_full_tick` 获取买一价、买一量，计算 `买一价 × 买一量` 作为封单金额近似值（若买一量较大）。或使用 Level2 数据中的 `bidVol1`‑`bidVol5` 加权。
  - 抗撤单因子 (CR)：若大QMT无法提供撤单历史，可考虑用 **竞价最后一分钟价格波动** 或 **开盘后第一分钟价格走势** 作为替代信号。
  - 确保 9:25 数据已稳定：延迟 2‑3 秒再计算，或使用 `get_market_data_ex` 指定 `time='09:25:00'` 参数（若支持）。
- **SPP 完整实现**：
  - 条件1：检查 `(open - lastClose)/lastClose < -0.03`。
  - 条件3：使用 `get_tick_series` 获取开盘后第一分钟成交明细，统计大单（单笔成交额 > 50万元）净流出。
  - 条件4：使用 `C.get_market_data_ex(['high'], ...)` 获取近期高点或成本均线。
- **MCP 量能确认**：
  - 在 9:30‑9:35 期间，每 tick 或每分钟记录成交量，计算 5 分钟平均每分钟成交量。
  - 触发时比较 `当前分钟成交量 > 5分钟平均 × 1.5`。

### 2. 执行时序优化
- 使用 `C.run_time` 注册多个定时任务：
  - `"09:25:30"`：执行 `prepare_daily_context`（留出数据稳定时间）
  - `"09:30:00"`：启动监控循环
  - `"09:45:00"`：停止买入信号
  - `"T+1 09:25:00"`：执行卖出逻辑
- 在 `handlebar` 中仅处理实时监控与触发，卖出逻辑移至独立定时任务。

### 3. 状态持久化方案
- 使用 `C.user_data` 或外部文件（如 `pickle`）存储关键状态（`target_sectors`, `candidate_pool`, `buy_count`, `is_melted`）。
- 在 `init` 中加载历史状态，在每次状态变更时保存。

### 4. 性能优化
- **批量获取数据**：将候选股列表合并，一次调用 `C.get_full_tick(candidate_codes)` 获取所有 tick，减少 API 次数。
- **缓存板块成分股**：在 9:25 计算后缓存板块成分股列表，避免反复调用 `C.get_stock_list_in_sector`。
- **异步计算**：若大QMT支持，可使用 `asyncio` 并发计算多个股票的 SPP/MCP，但需注意 handlebar 本身为同步循环。

### 5. 风控增强
- 实现 **龙头炸板保护**：在板块中识别涨幅最大、封单最强的个股作为“龙一”，监控其涨停状态，若在 10:00 前开板且 5 分钟未回封，将该板块从 `target_sectors` 移除，并停止该板块个股监控。
- 跌停计算使用个股的 **实际跌停板幅度**（可从 `get_instrument_detail` 获取 `LimitUpDownRate`）。

### 6. 代码健壮性
- 增加异常捕获与日志记录。
- 修复变量作用域错误（将 `sec_data` 提升到合适作用域或重新获取）。
- 验证 `get_full_tick` 返回的字段名（例如 `bidVol1` 还是 `bid_volume1`）。

## 五、审计结论

当前代码版本 **不符合实盘要求**，主要问题集中在因子计算不完整、数据获取不准确、风控缺失三个方面。建议按照上述优化建议进行全面重构，优先修复：
1. SS 因子的封单与抗撤单计算
2. SPP 的四个条件完整实现
3. MCP 的量能确认
4. 龙头炸板保护

重构后需进行 **历史回测** 与 **小资金实盘模拟**，重点验证：
- 9:25 板块筛选的命中率
- 9:30‑9:45 买入信号的胜率与盈亏比
- 全局熔断与账户熔断的有效性
