# 《情绪套利策略 Lite v3.0 - 免Level-2降级方案》

## 1. 核心设计思路

在**不使用Level-2行情接口**的约束下，通过以下策略实现核心逻辑：

1. **批量快照替代实时流**：用定时批量查询替代高频Tick监控
2. **技术指标替代深度数据**：用价格/成交量衍生指标替代买卖五档
3. **预筛选大幅减少监控标的**：从数百只缩减到10-20只
4. **延迟决策窗口**：从9:30-9:45延后到9:35-9:50，换取数据稳定性

---

## 2. 因子降级映射表

| 原因子 | 原数据依赖 | 降级方案 | 数据源 |
|:---|:---|:---|:---|
| **板块强度 (SS)** | 封单金额、撤单数据 | → 竞价涨停数量 + 竞价成交额排名 | 9:25快照（基础行情） |
| **抛压探测 (SPP)** | ~~买卖五档~~、大单流向 | → **保留买卖五档** + 量价背离检测 | **买卖五档（免费）** + 分时数据 |
| **题材协同性 (TS)** | 实时板块涨跌统计 | → 板块指数实时涨幅 | 板块指数行情 |
| **动量确认 (MCP)** | 实时Tick + 逐笔成交 | → 突破前5分钟高点 + 量比 | 1分钟K线聚合 |

**重要修正**：MiniQMT免费接口**可获取买卖五档数据**，因此抛压探测因子可以保留原策略的核心逻辑！

## 3. 降级后的量化因子定义

### 3.1 板块强度 Lite - `SS_Lite`

```python
SS_Lite = 0.6 * SR + 0.4 * VR

其中：
- SR (涨停共振因子) = 板块内竞价涨幅 > 9.5% 的个股数量
- VR (成交额强度) = 板块竞价总成交额 / 全市场竞价总成交额（取分位数排名）

筛选条件：
1. SS_Lite 排名前3
2. SR >= 3（至少3只涨停或接近涨停）
3. 板块指数竞价涨幅 > 2%

数据获取：9:25:00 一次性批量查询全市场竞价数据
```

### 3.2 抛压探测 Lite - `SPP_Lite`（保留买卖五档）

```python
SPP_Lite = 综合以下条件判断（任一为True则剔除）：

1. 买卖盘挂单失衡比（保留原策略）：
   Bid_Ask_Imbalance = (买一至买五总量) / (卖一至卖五总量) < 1.5
   # 直接使用MiniQMT的买卖五档数据

2. 量价背离因子 (VPD)：
   开盘后前3分钟：涨幅 > 0 但成交量 < 5日同时段均量的80%
   # 价涨量缩，缺乏买盘支撑

3. 套牢区接近度 (TRP)：
   现价距离60日均线 < 2%
   # 接近长期套牢区，抛压概率大

4. 开盘跌幅过滤：
   开盘涨幅 < 0%
   # 直接剔除开盘下跌股

数据获取：
- 9:30:00 获取开盘价 + 买卖五档（1次批量查询）
- 9:33:00 获取前3分钟成交量 + 买卖五档（1次批量查询）
- 历史均线数据（本地缓存，无需实时请求）
```

### 3.3 题材协同性 Lite - `TS_Lite`

```python
TS_Lite(t) = 板块指数实时涨幅

监控条件：
- 买入时刻，板块指数涨幅 >= 2%
- 从9:30至买入时刻，板块指数涨幅从未跌破1%

数据获取：
- 每分钟查询1次板块指数行情（9:30-9:50共20次）
- 仅查询3个目标板块指数，而非数百只个股
```

### 3.4 动量确认 Lite - `MCP_Lite`

```python
MCP_Lite 触发条件（需同时满足）：

1. 价格突破：
   当前价 > max(9:30-9:35的5根1分钟K线最高价)

2. 量比放大：
   当前1分钟成交量 > 前5分钟平均成交量的200%

3. 涨幅区间：
   当前涨幅 ∈ [3%, 7%]
   # 避免追高和弱势股

4. 无抛压信号：
   SPP_Lite = False

数据获取：
- 每分钟查询1次个股1分钟K线（9:35-9:50共15次）
```

## 4. 优化后的执行时间轴

| 时间 | 阶段 | 系统动作 | 请求次数 |
|:---|:---|:---|:---|
| **9:24:50** | 准备 | 加载本地缓存数据（均线、历史成交量） | 0 |
| **9:25:00** | 板块筛选 | **批量查询**全市场竞价数据，计算 `SS_Lite` | **1次**（全市场快照） |
| **9:25:30** | 目标锁定 | 选出3个目标板块，提取板块内个股列表 | 0（本地计算） |
| **9:29:50** | 个股预筛选 | 在3个板块内筛选：<br>- 竞价涨幅 ∈ [2%, 5%]<br>- 流通市值 > 20亿<br>- 非ST、非新股<br>**缩减到10-20只候选股** | 0（使用9:25数据） |
| **9:30:00** | 开盘数据采集 | **批量查询**候选股开盘价 | **1次**（10-20只） |
| **9:33:00** | 抛压初筛 | **批量查询**候选股前3分钟成交量，计算 `SPP_Lite` | **1次**（10-20只） |
| **9:33:30** | 监控池确定 | 剔除高抛压股票，最终监控池缩减到5-10只 | 0（本地计算） |
| **9:35-9:50** | 动态监控 | **每分钟批量查询**：<br>1. 监控池个股1分钟K线（5-10只）<br>2. 3个板块指数行情<br>判断 `MCP_Lite` 触发 | **15次** × (5-10只 + 3指数)<br>≈ **15次请求** |
| **9:50:00** | 窗口关闭 | 停止买入信号监控 | 0 |

**总请求量统计**：
- 9:25阶段：1次全市场快照
- 9:30-9:33：2次小批量查询（10-20只）
- 9:35-9:50：15次小批量查询（5-10只 + 3指数）
- **全天总计：约18次批量请求，单次查询标的数 < 20只**

### 5.4 增量更新而非全量查询

```python
# 仅查询变化的数据
class IncrementalMonitor:
    def __init__(self):
        self.last_snapshot = {}
    
    def update(self, stock_list):
        """仅更新价格和成交量，其他字段使用缓存"""
        new_data = batch_get_realtime_data(stock_list, fields=['price', 'volume'])
        for stock in stock_list:
            # 合并新数据和缓存数据
            self.last_snapshot[stock].update(new_data[stock])
```

## 9. 回测适配建议

1. **使用1分钟K线数据**进行回测，而非Tick数据
2. **模拟批量查询延迟**：每次查询增加0.5-1秒延迟
3. **滑点设置**：单边1%（比Level-2版本增加0.5%）
4. **信号触发时间**：统一在每分钟的第30秒判断（模拟数据到达延迟）

## 10. 实盘注意事项

1. **网络稳定性**：虽然请求频率低，但需确保9:25和9:30的关键时刻网络畅通
2. **时间同步**：本地时钟与交易所时间误差 < 1秒
3. **异常处理**：若某次批量查询失败，跳过本轮信号判断，等待下一分钟
4. **日志记录**：记录每次批量查询的响应时间，监控接口稳定性
