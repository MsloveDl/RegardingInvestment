# 情绪套利策略 v3.0 降级版（L2-Data-Efficient）

## 概述
本策略是《情绪套利策略 v3.0》的**数据高效降级版**，针对 MiniQMT（xtquant）环境优化。保留核心 L2 数据能力，但通过**批量请求、智能采样、降低频率**将数据流量减少 80-90%，适合实盘部署。

**核心理念不变**：不预测，只跟随。利用 9:25 竞价数据锁定最强板块，9:30-9:45 动态捕捉补涨个股。

---

## 核心原则

1. **批量请求优先**：使用 `xtdata.get_market_data`、`xtdata.get_l2_quote` 的批量接口，避免循环单票请求。
2. **智能采样**：监控池从全板块个股（~300+）缩减到 **开盘涨幅 Top 20**（每板块）。
3. **降低频率**：监控轮询从实时（秒级）降至 **15 秒/次**。
4. **数据复用**：买卖五档数据同时用于 SPP（抛压探测）和 MCP（动量确认）。

### 9:29:50：个股池初始化（智能采样）
```python
# 在每个目标板块内，只取开盘涨幅 Top 20
monitor_pool = []
for sector in top_sectors:
    stocks = xtdata.get_stock_list_in_sector(sector)
    changes = (quote['open'][stocks] / quote['pre_close'][stocks] - 1) * 100
    # 筛选：涨幅 +2% ~ +5%
    filtered = [s for s in stocks if 2 <= changes.get(s, 0) <= 5]
    # 取涨幅最大的 20 只（或最多 10%，取较小值）
    top20 = sorted(filtered, key=lambda s: changes.get(s, 0), reverse=True)[:20]
    monitor_pool.extend(top20)

# 总监控池：3个板块 × 20只 = 60只（远小于全板块300+）
```

**数据量**：无新增实时请求（复用 9:25 数据）。

### 9:30‑9:45：动态监控（低频批量）
```python
import time
from datetime import datetime

# 缓存前一次价格和成交量用于 MCP 计算
prev_price = {stock: None for stock in monitor_pool}
prev_volume = {stock: None for stock in monitor_pool}

while datetime.now().time() <= datetime.strptime('09:45:00', '%H:%M:%S').time():
    # 批量请求 60 只监控股的买卖五档 + 最新成交
    l2_batch = xtdata.get_l2_quote(monitor_pool)
    
    for stock in monitor_pool:
        data = l2_batch[stock]
        
        # 1. SPP 抛压探测（用买卖五档）
        bid_total = sum(data['bid_volumes'][:5])  # 买一到买五总量
        ask_total = sum(data['ask_volumes'][:5])  # 卖一到卖五总量
        imbalance = bid_total / ask_total if ask_total > 0 else 0
        
        if imbalance < 1.5:  # 买卖盘失衡
            continue  # 剔除
        
        # 2. TS 板块协同（用板块指数代替个股统计）
        sector_index = get_sector_index(stock)  # 预加载的板块指数实时涨跌
        if sector_index < 0.5:  # 板块跌幅>0.5%
            continue
        
        # 3. MCP 动量确认（用最新价 + 成交量）
        current_price = data['last_price']
        current_volume = data['volume']
        # 对比前一次快照的价格（需要缓存前一次数据）
        if prev_price[stock] and prev_volume[stock]:
            if current_price > prev_price[stock] and \
               current_volume > prev_volume[stock] * 1.5:
                trigger_buy(stock)
        
        # 更新缓存
        prev_price[stock] = current_price
        prev_volume[stock] = current_volume
    
    time.sleep(15)  # 15 秒轮询一次（原策略是实时）
```

**数据量**：每 15 秒约 60 只股 × L2 快照 ≈ 3-5KB。

## 风控与退出（与原版一致）

### T+1/T+2 滚动止盈止损
| 情景 | 退出规则 | 执行时间 |
| :--- | :--- | :--- |
| **常规止盈** | T+1 日 9:25 集合竞价全仓卖出 | T+1日 9:25:00 |
| **涨停持有** | T+1 日竞价封死涨停（≥9.8%）→ 持有至 T+2 竞价 | T+1日 9:25后 |
| **炸板卖出** | T+1 日盘中涨停后开板（炸板）→ 开板瞬间立即卖出 | T+1日盘中 |
| **动态止损** | 买入当日收盘价跌破 **5日移动平均线** 或 **当日分时均线** → 次日竞价卖出 | T日收盘判断，T+1日执行 |
| **时间止损** | 持仓最长不超过 **T+3** 个交易日 | T+3日 9:25 |

### 全局风控
- **账户熔断**：当日总浮动亏损 ≥ 3% → 停止所有新买入。
- **板块熔断**：龙头股在 10:00 前炸板且 5 分钟内未回封 → 放弃该板块。
- **仓位管理**：单股 5%，单日 ≤ 3 只，单板块 ≤ 15%。

## 注意事项

1. **数据准确性**：`get_l2_quote` 返回的字段名需实际验证（`bid_prices`、`bid_volumes`、`ask_prices`、`ask_volumes`、`last_price`、`volume`）。
2. **网络延迟**：15 秒轮询可能在某些急拉/急跌行情中错过最佳点，可考虑动态调整频率（如 9:35‑9:40 调至 10 秒）。
3. **板块指数**：`get_sector_index` 需自行实现（通过 `xtdata.get_market_data` 获取板块指数代码的实时行情）。
4. **历史快照**：9:19 的封单快照需盘前预加载（通过 `xtdata.download_history_data`）。
