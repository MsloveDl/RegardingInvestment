## 1. 策略定位 (Strategic Positioning)

本策略是 **Final_Sentiment_Arbitrage_Strategy** 与 **Qingyun_Quant_Analysis** 的深度基因融合产物。它保留了"情绪溢出套利"的竞价共振与筛选框架，同时深度整合了青云量化系统的 **AI动态感知、盘中确认、抛压探测与T+1/T+2滚动交易** 核心哲学。

**核心理念**：**不预测，只跟随**。利用开盘后**10分钟（9:35 - 9:45）** 的实时数据作为"全市场探针"，在强情绪板块中，精确捕捉抛压最小、动量最强的补涨个股，实现高周转、低回撤的超短线套利。

## 2. 核心逻辑总结：全市场探针式扫描 (9:35-9:45)

策略的核心是利用开盘后**10分钟（9:35 - 9:45）** 的市场"初态"数据进行实时决策，而非依赖预判。整个系统如同一张覆盖全市场的"神经探针网"：

1.  **环境感知 (9:25前)**：判断今日是否为"可交易日"。（全局开关）
2.  **板块雷达扫描 (9:25)**：锁定竞价阶段情绪最强、共振最明显的1-3个热点板块。（缩小战场）
3.  **龙头股识别 (9:25)**：在目标板块内识别"龙一"个股，用于板块熔断监控。
4.  **个股探针激活 (9:30-9:45)**：在目标板块内，对每只符合条件的个股启动"动态探针"，实时监控其：
    *   **抛压信号**（卖盘挂单深度、大单流向）。
    *   **动量信号**（价格突破、量比放大）。
    *   **协同信号**（与板块整体走势的同步性）。
5.  **信号合成与触发 (9:35-9:45)**：当单个个股的探针信号综合评分超过阈值，且板块环境依然健康时，系统自动下达买入指令。

**整个过程是动态、并行、条件触发的，完美融合了两种策略的优点。**

## 3. 关键定义与因子量化

### 3.1 龙头股识别标准

**龙一（板块龙头）**：满足以下条件综合评分最高的个股：
1. **涨幅优先**：竞价阶段涨幅最高的个股（权重40%）
2. **封单强度**：封单金额/流通市值比例最大的个股（权重30%）
3. **时间优先**：最早达到涨停价的个股（权重30%）

**龙头股作用**：
- 用于板块熔断监控（10:00前炸板保护）
- 作为板块情绪风向标

### 3.2 板块强度 (Sector Strength) - `SS`

用于在9:25筛选出全天可能最强的板块。

```
SS = W1 * SR + W2 * OR + W3 * CR

其中：
- SR (涨停共振因子) = 板块内竞价涨幅 > 9.5% 的个股数量。 (N_lu)
- OR (封单强度比) = (板块内涨停股总封单金额) / (板块流通总市值)。该值需进行全市场排名，取分位数排名（0-1）。
- CR (抗撤单因子) = 1 - (板块在9:24:50至9:25:00的总撤单金额 / 9:24:50总封单金额)。使用最后10秒数据减少噪声。
- W1, W2, W3 为权重，基础配置 [0.4, 0.3, 0.3]，支持动态调整。

筛选条件：SS 排名全市场前三，且 SR >= 3, CR > 0.6（提高标准减少噪声）。
```

### 3.3 抛压探测 (Selling Pressure Probe) - `SPP`

用于在9:30后剔除板块内的"弱势雷股"和"抛压沉重股"。

```
SPP = 综合以下布尔条件，任一为True则标记为高抛压，剔除：

1. 开盘跌幅 > max(3%, 市场平均波动率×1.5)  # 动态阈值
2. 买卖盘挂单失衡比 (Bid_Ask_Imbalance) 根据市值调整：
   - 大盘股（市值>500亿）：阈值 < 1.2
   - 中盘股（100-500亿）：阈值 < 1.5
   - 小盘股（<100亿）：阈值 < 2.0
3. 开盘后第一分钟大单净流出金额 > 昨日全天大单净流入的20%  # 简化历史依赖
4. 现价距离上方最近压力位（20日/60日高点、缺口、前期平台） < 3%  # 多重压力判断
```

### 3.4 题材协同性 (Thematic Synergy) - `TS`

用于在盘中确认板块热度是否持续，防止买入"板块内独立下跌股"。

```
上涨定义：当前价格 > 前一日收盘价 × (1 + 0.1%)  # 明确上涨标准
TS(t) = 板块内上涨个股数量 / 板块内总个股数量

动态监控条件：
- 买入时刻，TS(t) 必须 >= 70%。
- 监控窗口：从9:30至计划买入时刻，TS(t) 从未跌破60%。
```

### 3.5 个股动量确认点 (Momentum Confirmation Point) - `MCP`

最终的买入触发信号。**注意：交易窗口为9:35-9:45**

```
MCP 触发条件 (需同时满足)：
1.  实时价格 > 开盘后前5分钟（9:30:00 - 9:35:00）的最高价。
2.  触发时的成交量 > 开盘后前5分钟的平均每分钟成交量的150%。
3.  触发时，该个股的 SPP = False (即无高抛压信号)。
4.  触发时间必须在9:35:00之后（观察期结束）。
```

## 5. 风控与退出机制 (Risk & Exit)

### 5.1 持仓退出规则 (T+1/T+2 滚动止盈止损)

**执行顺序**：T+1日9:25:00按以下顺序检查并执行

| 情景 | 退出规则 | 执行时间 | 优先级 |
| :--- | :--- | :--- | :--- |
| **涨停持有检查** | 检查T+1日9:25:00是否封死涨停（涨幅≥9.8%且买一档有封单），如是则持有至T+2日竞价。 | T+1日 9:25:00 | 1 |
| **常规止盈** | 若不满足涨停条件，则在9:25:00集合竞价全仓卖出。 | T+1日 9:25:00 | 2 |
| **炸板卖出** | 若T+1日盘中涨停后开板（炸板），**开板瞬间立即卖出**。 | T+1日盘中 | 3 |
| **动态止损** | **买入当日（T日）**，若收盘价**同时**跌破 **5日移动平均线** 和 **当日VWAP（成交额加权均价）**，则次日竞价无条件卖出。 | T日收盘判断，T+1日执行 | 4 |
| **时间止损** | 无论盈亏，持仓最长不超过 **T+3** 个交易日。 | T+3日 9:25 | 5 |

### 5.2 全局熔断与账户风控

1.  **日内账户熔断**：当日所有持仓的 **总浮动亏损** 达到总资产的 **3%** 时，立即停止所有新的买入信号探测，且仅允许卖出操作。
2.  **板块熔断**：`龙头炸板保护`。若板块内识别出的"龙一"个股在10:00前涨停开板且5分钟内未回封，该板块即刻移出"目标板块"列表，并停止对该板块内所有个股的监控与买入。
3.  **滑点控制**：
    - **动态滑点**：根据过去5日平均买卖价差设置滑点（基础0.3%，小盘股上浮至0.8%）
    - **订单算法**：对超过50万元的订单使用TWAP算法分批执行
    - **流动性检查**：买入前检查个股流动性（过去5日均成交额>5000万）
4.  **仓位管理**：
    - 单只个股仓位：总资产的 **3-8%**，根据个股波动率动态调整（高波动3%，低波动5%，理想机会8%）
    - 单日最大开仓个股数：**2-5只**，根据市场情绪动态调整（情绪好4-5只，情绪差2-3只）
    - 单一板块最大暴露仓位：总资产的 **20%**（提高资金效率）
    - 总仓位限制：单日新增仓位不超过总资产的 **30%**

## 6. 代码实现要点 (Implementation Notes for Workstation)

### 6.1 系统架构优化

1.  **分层架构**：
    - **数据层**：统一数据接口，支持多数据源（券商L2、Wind、通联等）
    - **计算层**：分布式计算节点，每个节点负责10-20只个股的实时计算
    - **决策层**：中央决策引擎，汇总信号并执行风控

2.  **数据采样监控**：
    - 对个股监控采用**3秒采样**而非实时Tick，减少计算压力
    - 使用**滑动窗口**缓存最近5分钟数据，避免重复计算

3.  **状态管理**：
    - 使用**Redis**存储实时状态（监控状态、持仓、熔断状态）
    - **定期快照**：每5分钟保存状态快照，支持故障恢复
    - **操作日志**：记录所有关键操作，便于追溯

### 6.2 性能优化

1.  **个股池优化**：通过严格筛选将监控个股数量控制在50-100只以内
2.  **计算优化**：
    - 使用**向量化计算**替代循环
    - 对SPP、TS等因子进行**预计算**和缓存
    - 使用**JIT编译**（如Numba）加速关键计算
3.  **并发控制**：
    - 使用**asyncio**进行异步I/O操作
    - 计算密集型任务使用**multiprocessing**并行处理

### 6.3 数据依赖

1.  **实时数据**：
    - L2买卖五档（每3秒采样）
    - 成交明细（用于大单监控）
    - 板块成分股实时行情
2.  **历史数据**：
    - 前一日收盘价、成交量
    - 5日/20日/60日均线、高点
    - 过去5日波动率数据
3.  **竞价数据**：
    - 9:24:50-9:25:00的封单变化
    - 9:25:00的竞价成交额

## 7. 回测与优化方向 (Backtest & Optimization)

### 7.1 核心测试参数

1.  **动态参数系统**：
    - `SS`因子权重 (`W1, W2, W3`) 动态调整范围
    - `SPP`各子条件阈值适应不同市场环境
    - 仓位比例根据市场波动率动态调整

2.  **多市场环境测试**：
    - **牛市**（2020.7-2021.2）：测试进攻性
    - **震荡市**（2021.3-2022.4）：测试稳定性
    - **熊市**（2022.5-2022.10）：测试防御性
    - **极端行情**（2020.3、2022.3）：测试熔断机制

### 7.2 回测重点指标

1.  **绩效指标**：
    - 年化收益率 > 30%
    - 最大回撤 < 15%
    - 夏普比率 > 1.5
    - 胜率 > 55%
    - 盈亏比 > 1.8

2.  **执行指标**：
    - 信号触发率：5-15%（避免过度交易）
    - 平均持仓时间：1.2-1.8天
    - 滑点成本 < 0.5%（单边）
    - 订单成交率 > 95%

3.  **风险指标**：
    - VaR（95%，1天）< 3%
    - 连续亏损次数 < 5次
    - 单日最大亏损 < 5%

### 7.3 实盘过渡计划

1.  **小资金模拟**（1-3个月）：
    - 初始资金：1万元
    - 重点验证：下单速度、滑点真实情况、系统稳定性
    - 每日复盘：信号有效性分析、错误交易分析

2.  **逐步扩大**（3-6个月）：
    - 资金规模：5-10万元
    - 优化参数：根据实盘数据微调阈值
    - 完善监控：增加实时绩效监控面板

3.  **正式运行**（6个月后）：
    - 资金规模：根据回撤和风险承受能力确定
    - 建立备用策略：准备市场环境变化时的替代方案
